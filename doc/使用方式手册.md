# 本地 ArNS Gateway 使用方式手册

## 1. 运行要求

- Windows 10/11 或常见 Linux 发行版。
- Node.js 20 或更新版本。
- 首次解析新 ArNS 名称时需要互联网连接。
- 已镜像网站可以从本地永久对象库离线打开；网页自身的实时 RPC/API 功能仍可能需要网络。

不需要 Docker、Python、数据库、Solana 全节点或 Arweave 全节点。

## 2. 目录内安装

所有项目依赖都应位于本项目目录，禁止使用全局 npm 安装。

Windows PowerShell：

```powershell
Set-Location -LiteralPath '.\arns-local-gateway'
.\install-local.ps1
```

Linux/macOS：

```bash
cd /path/to/arns-local-gateway
npm ci --cache ./.npm-cache --no-audit --no-fund
```

安装结果：

```text
node_modules/   运行依赖
.npm-cache/     本项目专用 npm 下载缓存
```

项目内 `.npmrc` 将 npm 缓存固定到 `.npm-cache`。脚本不调用 `npm config set -g`，不写用户级 `.npmrc`，也不设置持久环境变量。

## 3. 启动

Windows：

```powershell
.\start.ps1
```

Linux/macOS：

```bash
npm start
```

默认监听 `127.0.0.1:4318`。浏览器打开：

```text
http://localhost:4318/
http://permapages.localhost:4318/
```

停止服务时在终端按 `Ctrl+C`。

## 4. 输入形式

首页支持：

```text
permapages
permapages.ar
ar://permapages
sam.arweave.dev
https://docs.ar.io/some/path
```

程序会将它们规范化为本地子域名形式，并保留路径。

## 5. 预下载与离线使用

预下载某个 Manifest 网站的全部路径资源：

```powershell
npm run mirror -- permapages
```

下载内容位于：

```text
.data/resolutions/   带 TTL 的 ArNS 解析记录
.data/objects/       不过期的 Data ID 对象和元数据
```

完成镜像后，即使 Solana RPC、Bundle 索引、Arweave Peer 和 raw 兜底全部不可用，静态文件仍可从本地打开。若网页 JavaScript 自己调用 Solana RPC、价格 API 或其他后端，相应动态区域仍需要网络。

## 6. RPC 与节点配置

程序默认提供多条候选，并按照配置顺序故障切换。

### Solana RPC

```text
https://solana-rpc.publicnode.com
https://public.rpc.solanavibestation.com
https://solana-mainnet.gateway.tatum.io
https://solana.api.pocket.network
```

用途仅为读取 ArNS Registry 和 ANT 账户，不用于下载网站文件。公共 RPC 可能限流、封禁或停止服务，生产部署应加入自己的付费或私有 RPC。

### Bundle 索引

```text
https://arweave-search.goldsky.com/graphql
https://turbo-gateway.com/graphql
```

它们只提供 `Data ID -> 父 Bundle ID` 元数据。文件字节仍从 Arweave Peer 读取。

### Arweave Peer

默认列表记录在 `.env.example`，只作为 seed。程序从 seed 以及上一次保存的节点快照开始 BFS 查询 `/peers`，去重后保存到：

```text
.data/peer-pool.json
```

默认每 6 小时重新构建一次快照。刷新成功后，未响应且没有被任何活节点再次提到的旧地址会被删除；如果整轮网络不可用，则保留旧快照，避免一次断网清空节点池。

下载时，交易 offset 和 Chunk 可以来自不同节点；每一个 Chunk 失败后都会换节点，并可沿失败节点的 `/peers` 逐层发现新候选。点对点节点不保证拥有所有历史 Chunk，因此 `/info` 在线只是初步健康信号。

检查当前所有端点：

```powershell
npm run check:endpoints
```

该检查确认：

- Solana RPC 的 `getHealth`。
- Bundle GraphQL 能执行查询。
- Arweave Peer 的 `/info` 属于 `arweave.N.1`。

`/info` 正常不代表节点拥有每个 Chunk；实际下载时程序仍会逐个 Peer 尝试。

Peer 发现相关配置：

```text
PEER_DISCOVERY_ENABLED=true
PEER_DISCOVERY_MAX_PEERS=512
PEER_DISCOVERY_MAX_DEPTH=2
PEER_DISCOVERY_CONCURRENCY=8
PEER_REQUEST_CONCURRENCY=8
PEER_REFRESH_INTERVAL_SECONDS=21600
```

## 7. 临时自定义配置

Windows PowerShell，仅对当前终端进程有效：

```powershell
$env:PORT = '4319'
$env:SOLANA_RPC_URLS = 'https://rpc-a.example,https://rpc-b.example'
$env:BUNDLE_INDEX_URLS = 'https://index-a.example/graphql,https://index-b.example/graphql'
$env:ARWEAVE_PEERS = 'http://node-a:1984,http://node-b:1984'
npm start
```

Linux/macOS，仅对该命令有效：

```bash
PORT=4319 \
SOLANA_RPC_URLS='https://rpc-a.example,https://rpc-b.example' \
ARWEAVE_PEERS='http://node-a:1984,http://node-b:1984' \
npm start
```

若希望禁止 raw Gateway 兜底：

```powershell
$env:DATA_PROVIDER_URLS = ''
npm start
```

项目不会自动读取 `.env`；如需长期配置，应由你选择的进程管理器注入，避免程序擅自修改系统环境。

## 8. 状态与诊断

```powershell
curl.exe http://localhost:4318/api/status
curl.exe 'http://localhost:4318/api/resolve?name=permapages'
npm test
```

网站响应头：

```text
x-local-arns-resolution-source
x-local-content-source
x-local-data-id
x-local-arns-target-id
```

常见来源值：

- `solana-rpc`：刚刚从链上解析。
- `resolution-cache`：命中 TTL 内解析记录。
- `resolution-cache-stale`：RPC 不可用，使用过期记录。
- `arweave-peer-chunks`：通过底层 Arweave Chunk 提取。
- `data-provider`：使用 raw 兼容兜底。
- `immutable-store`：完全从本地永久对象库返回。

## 9. 磁盘维护

- `node_modules` 和 `.npm-cache` 可通过重新安装恢复。
- `.data/objects` 是已下载网站的永久对象；删除后首次访问需要重新下载。
- `.data/resolutions` 可重建，但离线时需要它才能把 ArNS 名称指向本地对象。
- `.cache` 只属于旧 `proxy` 模式，`native` 模式不依赖它。

不要在不确认绝对路径的情况下批量删除这些目录。
