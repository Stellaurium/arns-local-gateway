# 安装与构建

本文说明如何从源码安装、启动和验证 ArNS Local Gateway。项目是 Node.js 应用，没有全局编译步骤；依赖和 npm 下载缓存都可以保留在项目目录内。

## 1. 系统要求

- Windows 10/11、常见 Linux 发行版或 macOS；
- Git；
- Node.js 20 或更高版本，安装 Node.js 时会同时得到 npm；
- 首次解析网站时可以访问 Solana RPC、Bundle GraphQL index 和 Arweave 网络节点；
- 建议预留至少 100 MiB 基础安装空间，另加实际访问网站产生的缓存空间。

确认工具：

```text
git --version
node --version
npm --version
```

如果 `node --version` 低于 20，请先从 Node.js 官方发行渠道升级。不要使用管理员权限运行本项目，也不需要全局安装 npm 包。

## 2. Windows：从零安装

打开 PowerShell，选择一个有空间的目录：

```powershell
Set-Location -LiteralPath 'C:\Projects'
git clone https://github.com/Stellaurium/arns-local-gateway.git
Set-Location -LiteralPath '.\arns-local-gateway'
.\install-local.ps1
```

安装脚本只在项目目录创建：

```text
node_modules/   运行依赖
.npm-cache/     npm 下载缓存
```

它不会修改系统环境变量，也不会写用户级 npm 配置。安装完成后启动：

```powershell
.\start.ps1
```

看到 `http://127.0.0.1:4318` 后，浏览器打开：

```text
http://localhost:4318/
```

## 3. Linux/macOS：从零安装

```bash
git clone https://github.com/Stellaurium/arns-local-gateway.git
cd arns-local-gateway
npm ci --cache ./.npm-cache --no-audit --no-fund
npm start
```

然后打开 `http://localhost:4318/`。服务默认只监听回环地址，不对局域网或公网开放。

如果浏览器环境不能自动解析 `name.localhost`，先用主页输入名称；也可以用下面的命令验证 Host 路由：

```bash
curl -H 'Host: permapages.localhost:4318' http://127.0.0.1:4318/
```

## 4. 配置（可选）

默认值已经可以直接运行。需要自定义时，把 `.env.example` 当作变量清单；程序不会自动读取 `.env` 文件，应在启动终端设置需要覆盖的变量。

PowerShell 示例：

```powershell
$env:PORT = '4319'
$env:DATA_DIR = '.data'
npm start
```

Bash 示例：

```bash
PORT=4319 DATA_DIR=.data npm start
```

完全禁用 raw Gateway 兼容兜底：

```powershell
$env:DATA_PROVIDER_URLS = ''
npm start
```

```bash
DATA_PROVIDER_URLS='' npm start
```

这仍会使用 Solana RPC、Bundle index 和普通 Arweave peer。它表示不再从公共 Gateway 获取文件正文，并不表示完全断网。

## 5. 验证安装

另开终端，在项目目录运行：

```powershell
npm test
npm run check:endpoints
```

- `npm test`：本地确定性测试；
- `check:endpoints`：检查当前配置的网络入口。

也可以预先下载一个 Manifest 网站：

```powershell
npm run mirror -- permapages
```

## 6. 数据、空间和卸载

运行后会在项目目录产生：

```text
.data/resolutions/   有 TTL 的 ArNS 解析缓存
.data/objects/       不失效的 Data ID 内容缓存
.data/peer-pool.json peer BFS 快照
```

程序不会下载整条 Arweave 链，也不会默认下载整个父 Bundle；磁盘随实际访问的对象增加。当前 Windows 安装实测 `node_modules` 约 37 MiB、`.npm-cache` 约 5 MiB，具体大小会随 Node.js、操作系统和依赖版本变化。网站缓存由访问内容决定，大型应用可能再增加几十到数百 MiB。

卸载时停止进程，然后删除整个项目目录即可。项目没有注册系统服务，也没有全局安装依赖。只想清理网站缓存时，可以在服务停止后删除项目内的 `.data`，但这会失去已下载网站的离线副本与 peer 快照。

## 7. 更新

先停止服务，在没有未保存本地修改的前提下执行：

```powershell
git pull --ff-only
.\install-local.ps1
```

Linux/macOS：

```bash
git pull --ff-only
npm ci --cache ./.npm-cache --no-audit --no-fund
```

`npm ci` 根据锁文件重建依赖，适合可重复安装。

## 8. 常见故障

### 页面第一次打开很慢

冷访问需要解析 ArNS、定位 Bundle、发现 peer 并下载多个文件。等待完成后，已取得的 Data ID 会从本地不可变对象库返回。

### 一个 peer 返回 404

程序会对 offset 和每个 Chunk 跨多个 peer 重试，并可沿 `/peers` BFS 发现新节点。单个节点 404 不会立即判定整个对象不存在。

### 首页能打开，但某项业务失败

网站自己的 JavaScript 仍可能依赖钱包、AO、Solana RPC、上传、支付或其他 API。本 Gateway 只负责解析和提供 Permaweb 文件。

### 端口被占用

设置其他端口，例如 PowerShell：

```powershell
$env:PORT = '4319'
npm start
```

随后打开 `http://localhost:4319/`。

### 想对局域网或公网开放

当前项目按本地使用设计。公网部署前必须增加 HTTPS、认证、限流、日志脱敏和滥用防护；不要仅把 `HOST` 改为 `0.0.0.0` 就直接暴露到互联网。
