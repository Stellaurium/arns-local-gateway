# 兼容性测试

测试日期：2026-10-09。版本：0.3.0。环境：Windows、Node.js 24.15.0、Chromium。

这些结果是当次网络和 ArNS 映射的观测，不保证公共服务始终可用。项目仍处于 Alpha 阶段。

## 冷启动方法

每个站点使用独立、初始为空的数据目录，以及全新的浏览器上下文，不复用 ArNS 解析、对象、peer/RPC 快照、浏览器缓存或登录状态。保留原使用目录中的缓存，避免删除已有离线副本。

以下成功加载站点的复测均设置 `DATA_PROVIDER_URLS=''`，禁止服务端 raw Gateway 文件兜底。网站文件通过普通 Arweave peer 的 offset/Chunk 获取；Solana RPC 与 Bundle GraphQL index 仍是网络依赖。网页自身引用的 CDN、组件和业务 API 不受这一设置限制，不能把结果称为完全无第三方或断网运行。

除检查 HTTP 状态外，还检查标题、页面内容、浏览器异常、资源请求和截图；交互仅限导航、播放按钮和打开登录选项，不导入钱包、不发送交易、不支付、不上传文件。

## 本轮发现并修复的问题

- 压缩 HTML 被当作普通文本：保留 Content-Encoding 标签，路由及响应前有界解码，磁盘仍存原始不可变字节。
- 并发 peer 读取等待整批最慢节点：取第一个成功响应并取消其余请求，正文读取也受超时约束。
- 相同 Data ID 并发下载及临时文件冲突：合并在途请求，使用唯一临时文件名。
- 瞬时连接中断：幂等索引/provider 读取允许一次有界重试，不重试拒绝、404、429 或证书错误。
- 名称不存在和网络故障混淆：确认名称不存在返回 404，不返回过期映射。
- 强制解析刷新被普通缓存请求合并：按名称和刷新模式区分，强制刷新不被缓存命中吞掉。
- RPC 总期限耗尽时未启动发现：请求按时结束，同时允许有界后台发现为后续请求补充节点。

## 本地回归与复测

```sh
npm test
npm run check:endpoints
```

本轮 43 项确定性测试通过。包括 TTL/过期回退、HTTP 304/404、只读 RPC 桥接、精确整数、429/方法级切换、BFS、压缩 Manifest/HTML、解压尺寸限制、并发下载和瞬时读取重试。确定性测试不请求公共网络；实站结果另行记录。

还在项目内隔离目录仅放置 `package.json` 和锁文件，执行离线 `npm ci` 完成全新依赖安装，再复制源码与测试运行全部 43 项测试，均通过；没有复用原目录的 `node_modules`，也没有全局安装。

当次 `check:endpoints` 中，五个默认 Solana RPC 均支持 `getSlot` 和基础 `getAccountInfo`。VibeStation 与官方主网 RPC 的小规模 `getProgramAccounts` 探测成功；PublicNode、Pocket、Tatum 对该方法返回限制错误。这个探测不是任意程序扫描、大批量读取或长期可用性的保证。两个 Bundle index 可访问，五个 Arweave seed 中四个健康；文件请求仍按具体 offset/Chunk 跨节点重试。

手动复测可用新的 `DATA_DIR` 启动服务，并在全新浏览器上下文中访问。PowerShell 示例：

```powershell
$env:DATA_DIR = '.tmp/cold-manual'
$env:DATA_PROVIDER_URLS = ''
npm start
```

每轮换一个尚不存在的目录名，确认没有继承旧缓存。变量仅作用于该终端；原数据目录不用删除。进入站点后检查界面、开发者工具中的 Network/Console 和 `X-Local-Content-Source`，不能仅凭 HTTP 200 判定兼容。
